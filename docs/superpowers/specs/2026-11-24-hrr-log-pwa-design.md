# HRR 測試事件紀錄 PWA（hrr-log）設計

## 目的

跑步機心率恢復（HRR）測試中，心率已由裝置自動記錄，但暖身、跑步開始、停止跑步、恢復結束等時間點與已完成組數仍靠手動紀錄，常有數秒誤差或紀錄矛盾（例如 2026-11-13 備註寫 60 秒休息，實際為 90 秒）。停止跑步的時間點直接決定恢復曲線起點，誤差會原樣進入 TD、work-HR、HRR60 與 HR90。

本 app 讓研究人員在測試中以按鈕即時記錄帶有狀態標籤的事件，並匯出 CSV，供 HRR 分析程式切段使用。

## 範圍

本規格只涵蓋子專案 1：事件紀錄 PWA。

不在本規格範圍：

- 連接 Polar H10、手錶或跑步機（本版不做任何藍牙或裝置連線）。
- 雲端儲存或上傳資料。
- HRR 分析端讀取 CSV、對時與切段（子專案 2，待取得實際紀錄後另立規格）。

## 平台與部署

- 形式：PWA（Progressive Web App），可加到手機主畫面並離線使用；iPhone、Android 與筆電瀏覽器共用同一份程式。
- 技術：純 HTML、CSS 與 JavaScript（ES modules），不使用框架、不需建置步驟、不安裝套件。
- 原始碼：`C:\Wen_Files\GPT_Projects\hrr-log\`，獨立 git repo。
- 發布：GitHub 公開 repo `wenlab501/hrr-log`，GitHub Pages 由 `main` 分支根目錄提供，網址 `https://wenlab501.github.io/hrr-log/`。repo 只含程式碼，不含任何受試者資料。
- 建立 repo、推送與開啟 Pages 屬對外發布，執行前須取得使用者確認。

## 資料保存原則

- 所有紀錄只存在操作裝置的瀏覽器本機儲存（IndexedDB），不上傳至 GitHub 或任何伺服器。
- app 不含分析追蹤、廣告或外部請求；離線後所有功能可用。
- 受試者只以代碼識別；建立場次時提示「請勿輸入姓名」。
- 每場測試結束後匯出 CSV，由研究人員存至 Google Drive 或專案資料夾。

## 資料模型

### 場次（session）

| 欄位 | 說明 |
|---|---|
| `session_id` | 隨機 UUID |
| `participant_code` | 受試者代碼（必填，不得為姓名） |
| `protocol_label` | protocol 名稱，自由文字，例如「漸增 6+1 km/h」「9 km/h × 4 min」 |
| `operator` | 操作者代碼（選填） |
| `created_epoch_ms` | 建立時間 |
| `exported` | 是否已匯出過 |
| `app_version` | 建立時的 app 版本 |

### 事件（event）

事件只新增、不修改、不刪除。

| 欄位 | 說明 |
|---|---|
| `session_id` | 所屬場次 |
| `seq` | 場次內事件序號，從 1 起 |
| `event_type` | `sync`、`warmup_start`、`run_start`、`run_stop`、`recovery_end`、`cooldown_start`、`test_end`、`rpe`、`note`、`correction` |
| `bout` | 組數：每個未被更正的 `run_start` 使組數加 1；其他事件帶入當下組數 |
| `speed_kmh` | `run_start` 時記錄的速度；預設帶入上一組速度，可用 ±0.5 km/h 調整 |
| `rpe` | `rpe` 事件的 1–10 整數 |
| `note` | 文字備註 |
| `t_epoch_ms` | 手機絕對時間（`Date.now()`） |
| `t_local_iso` | 本地時間 ISO 8601 字串，含時區位移 |
| `t_mono_ms` | 自場次開始起算的單調時間（`performance.now()` 差值；重新開啟頁面後以「最後事件的單調時間＋實際經過時間」接續，並在該事件標記 `resumed`） |
| `corrects_seq` | `correction` 事件指向被撤銷的事件序號 |
| `flags` | 以分號分隔的標記，例如 `resumed`、`clock_jump` |

### 狀態推算（`state.js`）

由有效事件（排除被 `correction` 撤銷者）推算：

| 最後一個狀態事件 | 目前狀態 |
|---|---|
| 無 | 未開始 |
| `warmup_start` | 暖身中 |
| `run_start` | 第 N 組跑步中 |
| `run_stop` | 第 N 組恢復中 |
| `recovery_end` | 第 N 組恢復結束 |
| `cooldown_start` | 緩和中 |
| `test_end` | 已結束 |

`sync`、`rpe`、`note` 不改變狀態。

補充規則：

- 每個有效的 `run_start` 都使組數加 1，即使前一組沒有 `run_stop`（此時另顯示異常提示）。
- 「撤銷上一筆」只作用於最後一筆有效、且不是 `correction` 的事件；`correction` 本身不能再被撤銷。撤銷後的組數與狀態一律由剩餘的有效事件重新推算。

## 介面

手機直式、單手操作，按鈕大小至少 64 × 64 px。

1. **首頁**：建立新場次（受試者代碼、protocol 名稱、操作者），列出歷史場次，未匯出者標示「未匯出」；可重新匯出或刪除（刪除須二次確認，且提示無法復原）。
2. **測試畫面**
   - 頂端狀態列：受試者代碼｜目前狀態（例如「第 3 組｜恢復中」）｜本狀態經過秒數｜測試總時間。
   - 事件按鈕（兩欄）：跑步開始（旁顯示即將使用的速度與 ± 鍵）、停止跑步、恢復結束、暖身開始、緩和開始、同步。
   - 依目前狀態加亮最可能的下一個按鈕；所有按鈕皆可按，不強制順序。
   - 按下 `run_stop` 後跳出 RPE 1–10 快速選單，可略過；之後可隨時以 RPE 按鈕補記。
   - 底部：備註、撤銷上一筆（產生 `correction` 事件）、最近 5 筆事件、測試結束（長按 1 秒或二次確認）。
3. **異常提示**（只提示，不阻擋）
   - 連續兩次 `run_start` 之間沒有 `run_stop`。
   - `run_stop` 前沒有對應的 `run_start`。
   - 本組休息時間與前幾組中位數相差超過 30 秒。
   - 偵測到時鐘跳動。

## 匯出

- 觸發：按「測試結束」時自動產生；首頁可對任一場次重新匯出。
- 方式：支援 Web Share API 時叫出分享選單（可直接存至 Google Drive）；否則下載檔案。
- 檔名：`HRR-log_<受試者代碼>_<YYYYMMDD-HHMM>.csv`；受試者代碼中 Windows 不允許的字元以 `_` 取代。
- 編碼：UTF-8 含 BOM，換行為 CRLF，Excel 開啟中文不亂碼。
- 內容：開頭以 `#` 起始的註解列記錄場次欄位與 app 版本；之後為表頭與每列一筆事件，包含被撤銷的事件與 `correction` 事件，以保留稽核軌跡。另加 `valid` 欄（被撤銷者為 `false`），方便分析端直接篩選。
- 匯出成功後將場次標為 `exported`。

## 錯誤處理

- 每次按鍵立即寫入 IndexedDB；寫入失敗時畫面顯示紅色警示，並保留在記憶體中可重試。
- 頁面重新整理、關閉或當機後重開，自動回到進行中的場次並接續。
- 測試畫面啟用 Screen Wake Lock；不支援時顯示「請關閉自動鎖定」。
- 時鐘跳動：比較相鄰事件的 `t_epoch_ms` 差與 `t_mono_ms` 差，相差超過 2 秒時在後一筆事件標記 `clock_jump`。
- 儲存配額或瀏覽器清除風險：首頁持續提示未匯出場次。

## 測試

1. **單元測試**（`node --test`，不安裝套件）
   - 組數累計：多組 `run_start`／`run_stop` 與撤銷後的組數。
   - 狀態推算與經過時間。
   - 異常提示規則。
   - 更正紀錄套用（`valid` 欄）。
   - CSV：欄位順序、BOM、CRLF、逗號與引號跳脫、中文備註、檔名字元替換。
   - 時鐘跳動偵測。
2. **瀏覽器檢查**：本機靜態伺服器（暫存檔放在專案外），以內建瀏覽器手機尺寸操作；確認狀態列、按鈕、重新整理後接續、離線可用、CSV 內容正確。
3. **真機演練**：使用者在手機安裝後，搭配碼錶模擬一場測試，比對 app 記錄的間隔與碼錶。

## 與 HRR 分析的銜接（子專案 2，僅記錄方向）

- 讀取 CSV、篩選 `valid`，產生與 `ProtocolWindow` 相同結構的工作與恢復區段。
- 以 `sync` 事件換算 app 與心率檔的時間差，再以停止跑步後心率下降起點或 FIT 速度下降估計殘餘偏差。
- 以同時有 FIT 速度資料的場次，比對事件切段與速度自動切段的一致性。

## 已決定事項

- 暖身只以 `warmup_start` 事件記錄時間點；app 不記錄也不檢查暖身強度條件。計畫書的暖身條件（Borg 6–20 量表的 RPE < 11）維持原文，由研究人員依計畫書執行。
- app 的 RPE 1–10 只用於各組停止跑步後的紀錄，與計畫書暖身條件使用的量表不同；分析時不可將兩者直接比較。

## 版本

- app 版本以語意化版本（例如 `0.1.0`）顯示於畫面與 CSV 註解列；`sw.js` 的快取名稱含版本號，更新後重新開啟即套用新版。
